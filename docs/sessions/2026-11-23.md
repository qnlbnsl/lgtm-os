# Session report: 2026-11-23

LGTM OS, from first idea to three pushed commits (`012030d`, `4c01dbc`, `578d908`).
Nothing has booted yet: no full ISO build, no VM run. Everything below marked
"verified" was checked on the build machine without booting.

## Goal

An Arch-based, all-in-one OS for agentic work, gaming and everything else. The system
plus display manager fits in 128 MB of RAM; apps may use more. Windows, Linux, Android
and Mac apps run like native ones. Priorities: speed, light weight, open source, just
works. Look: frosted glass, Mac-like.

## What exists now

**Base and session**
- archiso build (`build.sh`: packages, profile, iso) with a local `[lgtm]` pacman repo
  that ships on the ISO for offline use. Kernel: linux-zen.
- greetd, then `lgtm-session`, which starts one of two modes:
  - glass: Wayfire with blur
  - lite: labwc
  
  The mode is picked from RAM and GPU. One waybar process draws both the top bar and
  the dock.
- Memory tuning: zram, earlyoom, volatile journal. Networking: iwd + systemd-networkd.

**Running apps**
- Windows: Wine plus bundled GE-Proton (`lgtm-ge-proton`, updated weekly) through
  umu-launcher; `.exe` files open via binfmt.
- Android: Waydroid, started on demand.
- Mac: Darling (preview).
- Teams: teams-for-linux.
- Any package type: `lgtm-open` handles `.deb` and `.rpm` (distrobox), AppImage and
  Flatpak.

**Installer** (`lgtm-install`)
- Asks for the keyboard style (macOS or Windows), the theme, disk encryption (LUKS2,
  unlocked at the Plymouth splash, then auto-login, as on Omarchy), and setup profiles.
- Boot is quiet behind a hidden GRUB menu. Without auto-login, the login screen is
  ReGreet running in cage.

**Keyboard styles** (`lgtm-keys`)
- Per-style bindings for Wayfire and labwc, merged at login.
- With the macOS style, keyd maps ⌘C/⌘V/⌘X to Ctrl+Insert, Shift+Insert and
  Shift+Delete, so they work in every app.

**Themes** (`lgtm-theme`)
- Aurora (the default blue) and macOS Graphite (WhiteSur icons and the macOS cursor,
  both prebuilt into the offline repo).
- Users can add their own themes in `~/.config/lgtm/themes`.
- Switching applies to the running desktop (`lgtm-session --apply`).
- Each theme's package needs live in a plain `packages` file, installed by `lgtm-pkg`.
  `aur:` lines are built from the AUR on the machine.

**Setup profiles** (`lgtm-setup`)
- Three profiles: gaming, vm, dev.
- Choices made in the installer run in a terminal at first login, once there's
  internet.

**Virtual machines** (`lgtm-vm`)
- A wizard for any OS. quickget downloads Windows 11 from Microsoft and about 100
  other OSes; a link or a local file also works.
- Graphics, in order:
  1. A spare GPU passed through, including a laptop's render-only GPU, shown in
     Looking Glass B8-rc1 (its virtual display driver means no dummy plug).
  2. A slice of the Intel GPU via SR-IOV (i915-sriov-dkms, experimental).
  3. VirGL, for Linux guests.
  4. A plain virtual display.
- Laptop NVIDIA fixes: a fake battery ACPI table, the laptop's subsystem IDs, and the
  vBIOS when it can be read.
- GPUs reserved for VMs are hidden from the compositor via WLR_DRM_DEVICES.
- The `lgtm-tuning` libvirt hook reserves hugepages and isolates CPUs, read from the
  domain XML. This is a generic port of the user's mainpc `win11-tuning` hook.

**Containers** (`lgtm-pod`)
- A distrobox wizard. Apps installed with `lgtm-pod install` are exported to the menu.

**AI integration**
- `lgtm-agent` picks Claude Code, Codex, opencode or Gemini.
- LGTM OS skills are linked into every agent's skills folder.
- `lgtm-crash`: a path unit that watches for coredumps, so it uses no RAM while idle.

**Licensing**
- GPL-3.0-or-later.
- `NOTICE.md`, plus `lgtm-notices`, which regenerates `/usr/share/lgtm/NOTICES.md` from
  pacman after every package change.

## Decisions (and why)

- **Name:** LGTM OS (originally "Feather"). Repo: `qnlbnsl/lgtm-os`. Proton:
  GE-Proton only.
- **Login:** greetd rather than SDDM. SDDM keeps its own compositor running.
- **Encryption:** the encrypted install mirrors the user's Omarchy flow: one password
  at the splash, then auto-login.
- **Package installs:** `.deb` and `.rpm` go through podman/distrobox (the user's
  choice).
- **Dictation:** Wispr Flow was declined. A whisper.cpp alternative was offered but
  not built.
- **Looking Glass:** single monitor only. The user's multi-screen hacks were dropped:
  windows-cursor-bridge, the A1000 guard and Hyprland workspace rules.
- **Looking Glass version:** B8-rc instead of B7, because laptop GPUs have no ports and
  only B8 needs no dummy plug. The Windows side must also run B8.
- **Windows VM disk:** SATA (Windows Setup sees it without drivers), at some cost to
  speed. Linux guests use virtio.
- **AUR builds:** heavy builds (Looking Glass, Heroic, quickemu) happen on the target
  through `lgtm-pkg`. Only plain asset or `-bin` packages are built into the ISO repo.

## Verified

- Package builds; no file conflicts against the ISO's packages.
- Theme × mode × keyboard style combinations generate valid configs.
- GTK accepts the waybar CSS.
- `.lnk` parsing, the Proton updater, `lgtm-open` dispatch, agent skill linking, crash
  dedupe, and notices generation.
- `lgtm-vm gpus` on the build laptop (i7-1165G7, Iris Xe with 7 SR-IOV slices, GTX 1650
  Ti Mobile as a render-only GPU in its own IOMMU group).
- Generated domain XML is valid for:
  - Windows with passthrough
  - Windows with a plain display
  - Linux with VirGL (uses the Intel render node, renderD129)
  - Linux with passthrough
